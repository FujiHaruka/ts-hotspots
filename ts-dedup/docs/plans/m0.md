# M0: プロジェクト基盤とドメイン型定義

[docs/plans/milestones.md](./milestones.md) の M0 の実装計画。

## 目的

後続マイルストーン (M1〜M8) が参照する共通ドメイン型、ディレクトリレイアウト、テスト基盤、設定体系を整える。`pnpm typecheck` / `pnpm test` / `pnpm lint` が通るところまで。

## Approach

- **型のみ先に固める**: Fragment / Feature / Posting / InvertedIndex / Candidate / CandidateScore / CloneCandidateReport / Config の「データとしての契約」を先に TypeScript 型として切る。実装関数はまだ書かない。後段の実装者 (M1〜M6) がこの型を参照して各段を作る。
- **Config は値だけを持つ**: config の型と既定値だけを置き、読み込み (ファイル / CLI) は M7 に寄せる。v1 の既定値は requirements.md / v1.md の記述 (n-gram 長、候補件数、スコア重み、OR 閾値) を素直に反映。
- **ディレクトリは pipeline に沿う**: `src/domain/` にドメイン型、`src/config/` に既定値。実装モジュールは M1 以降で `src/indexer/ src/features/ src/index/ src/search/ src/scoring/ src/diff/ src/report/` に分ける。
- **テスト雛形は 1 本だけ**: vitest が走ることを確認するためのスモークテストを置く。fixture を置く空ディレクトリを `test/fixtures/` として用意。
- **verbatimModuleSyntax 対応**: type-only の再エクスポートは `export type {}` を明示する。
- **noUncheckedIndexedAccess 対応**: ドメイン型はすべて optional でないフィールドは必須とし、呼び出し側で optional index に備える。

## 成果物とディレクトリ構造

```
src/
  domain/
    fragment.ts        # Fragment, FragmentKind, StatementKindId
    feature.ts         # Feature, FeatureKind, FeatureKey
    index.ts           # Posting, InvertedIndex
    candidate.ts       # Candidate, CandidateScore, ScoreBreakdown
    report.ts          # CloneCandidateReport, ReportCandidate, Evidence, RecommendationHint
    index.ts (barrel)  # 名前衝突回避のため最終的に src/domain/index.ts はバレル、
                       # ファイル名は fragment.ts / feature.ts / posting.ts / candidate.ts / report.ts にする
  config/
    config.ts          # Config 型
    defaults.ts        # defaultConfig
  index.ts             # 既存のスケルトンを残す (M7 で書き換え)
test/
  fixtures/            # 空ディレクトリ + .gitkeep
src/
  smoke.test.ts        # vitest が動くことの確認
```

※ `src/domain/index.ts` との衝突を避けるため、posting 用のファイル名は `posting.ts` とする (「index」の多義性回避)。

## 型の詳細

### Fragment

```ts
export type FragmentKind = "function" | "block" | "window";

export type Fragment = {
  id: string;          // 例: "src/a.ts#12-34-function"
  filePath: string;
  startLine: number;   // 1-based, inclusive
  endLine: number;     // 1-based, inclusive
  kind: FragmentKind;
  text: string;        // 元ソース
  astNodeKind: string; // "FunctionDeclaration" 等。string で持ち、ts.SyntaxKind 依存をここで閉じる
};
```

- id の規約: `${filePath}#${startLine}-${endLine}-${kind}` + 必要なら disambiguator。安定性のため「AST 位置」ではなく「ファイル上の行範囲 + kind」で決める。M1 で window の重複/同一位置のケースを見て調整する。

### Feature

```ts
export type FeatureKind = "token" | "statement" | "call";

export type FeatureKey = string;   // "token:IF ID DOT ID" のような prefixed string

export type Feature = {
  kind: FeatureKind;
  key: FeatureKey;     // prefix 付き
};

export type FragmentFeatures = {
  fragmentId: string;
  tokens: FeatureKey[];       // token n-gram の key 列 (重複可、スコアリングで bag として利用)
  statements: FeatureKey[];   // statement kind n-gram
  calls: FeatureKey[];        // call / prop / awaitCall fingerprint
};
```

### Posting / InvertedIndex

```ts
export type Posting = {
  fragmentId: string;
  filePath: string;
  startLine: number;
  endLine: number;
  featureKind: FeatureKind;
};

export type InvertedIndex = {
  // key: FeatureKey (prefix 付き), value: posting の配列
  readonly postings: ReadonlyMap<FeatureKey, readonly Posting[]>;
};
```

### Candidate / Score

```ts
export type Candidate = {
  changedFragmentId: string;
  baseFragmentId: string;
  hitCounts: {
    token: number;
    statement: number;
    call: number;
  };
};

export type ScoreBreakdown = {
  tokenOverlap: number;
  statementKindSimilarity: number;
  callOverlap: number;
  sizeCompatibility: number;
};

export type CandidateScore = {
  changedFragmentId: string;
  baseFragmentId: string;
  combined: number;
  breakdown: ScoreBreakdown;
};
```

### Report

```ts
export type Evidence = {
  sharedCalls: string[];
  sharedProperties: string[];
  matchedStatementKinds: string[];
  matchedTokenNgramsSample: string[];
};

export type RecommendationHint = {
  confidence: "low" | "medium" | "high";
  likelyRefactoring: "extract-function" | "parameterize" | "manual-review";
  riskFlags: string[];
};

export type ReportCandidate = {
  changed: {
    filePath: string;
    startLine: number;
    endLine: number;
    kind: string;
    code: string;
  };
  existing: {
    filePath: string;
    startLine: number;
    endLine: number;
    kind: string;
    code: string;
  };
  scores: {
    combined: number;
    tokenOverlap: number;
    statementKindSimilarity: number;
    callOverlap: number;
    sizeCompatibility: number;
  };
  evidence: Evidence;
  recommendationHint: RecommendationHint;
};

export type CloneCandidateReport = {
  pr: {
    baseSha: string;
    headSha: string;
  };

};
```

### Config

```ts
export type ExcludeRules = {
  globs: string[];  // minimatch の glob
};

export type Config = {
  exclude: ExcludeRules;
  fragment: {
    statementWindowSizes: number[]; // 既定: [5, 10, 20]
    statementWindowStride: number;  // 既定: 3 (重複抑制)
  };
  features: {
    tokenNgramSizes: number[];     // 既定: [3, 4, 5, 6]
    statementNgramSizes: number[]; // 既定: [2, 3, 4, 5]
  };
  search: {
    maxCandidatesPerFragment: number; // 既定: 100
  };
  scoring: {
    weights: {
      token: number;     // 既定 0.40
      statement: number; // 既定 0.30
      call: number;      // 既定 0.20
      size: number;      // 既定 0.10

    thresholds: {
      combined: number;  // 既定 0.30
      token: number;     // 既定 0.35
      statement: number; // 既定 0.45
      call: number;      // 既定 0.40
    };
  };
};
```

## テスト雛形

- `src/smoke.test.ts`: `defaultConfig` を読み出すだけの assertion 1 本。vitest / typecheck / eslint が回ることを確認する。
- `test/fixtures/.gitkeep`: 空ファイルでディレクトリだけ存在させる。

## リスク / 留意点

- **型の過剰設計を避ける**: M1〜M6 が実装に入ったときに必要になった型は都度追加する。M0 で決めるのは「pipeline 全体が共有する語彙」だけ。
- **FeatureKey の prefix**: prefix を付ける (`token:...`, `statement:...`, `call:...`) ことで、転置索引の key 名前空間衝突を避ける。M2 の実装者はこの規約を守る。
- **Fragment.id の安定性**: `noUncheckedIndexedAccess` 下で Map 系を扱うため、id 生成が決定的であることが決定性 (要求 5.2) に直結する。
