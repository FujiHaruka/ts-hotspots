# M1: Fragment 抽出 (Codebase Indexer)

[docs/plans/milestones.md](./milestones.md) の M1 の実装計画。

## 目的

TypeScript ソース (`.ts` / `.tsx`) を `typescript` パッケージでパースし、Type-3 duplication 検出の比較単位となる fragment に分割する。v1.md / requirements.md の 3 粒度をすべてサポートする:

1. **function**: function declaration / method / arrow function / function expression
2. **block**: `if` / `for` / `while` / `do-while` / `try` / `catch` / `switch`
3. **window**: 連続する N 文のスライディングウィンドウ (block の `statements` 配列単位)

成果物は「fragment の配列」。永続索引化は M3 で別モジュールに切り出す。

## Approach

- **パーサ選定**: `typescript` パッケージ (`ts.createSourceFile`)。v1 は型検査に依存しないので `Program` は不要。1 ファイル単位で `SourceFile` を作り再帰的に訪問する。`ScriptKind` は拡張子 (`.tsx` なら `TSX`、それ以外は `TS`) から決める。
- **訪問戦略**: `ts.forEachChild` でツリーを再帰下降する。関数・メソッド・アロー・制御ブロックのいずれかの条件に当てはまるノードで fragment を生成し、さらに子ノードへ降りる (関数の中の関数、if の中の for、などを両方拾う)。
- **window 戦略**: `ts.Block | ts.SourceFile | ts.ModuleBlock | ts.CaseClause | ts.DefaultClause` のような `statements` を持つノードを見つけたら、その statements 配列に対して config で指定された各 size / stride でスライディング window fragment を生成する。ネストされた block の外側は外側で、内側は内側で個別に window を作る。
  - `statementWindowSizes: [5, 10, 20]`, `statementWindowStride: 3` (M0 既定)。
  - window は「statements 配列の連続部分列」なので、重複は発生するが本質的に異なる特徴空間になる。重複排除は M8 で判断する。
  - 文数が size 未満の block では該当 size の window を作らない (短すぎる window は n-gram の意味が薄い)。
  - **短い block のフォールバック**: block/source の文数が最小 window size 未満 (例: 5 未満) の場合でも、文が 2 件以上あればその「全体」を 1 個の window として作る。小さな helper の重複を拾うのに必要。
- **行番号**: `ts.getLineAndCharacterOfPosition(sourceFile, pos)` から 0-based line を取り、**1-based** に変換して格納する (人間向け表示の一貫性のため)。
- **text**: Fragment の元ソースは `sourceFile.text.slice(node.getStart(sourceFile), node.getEnd())`。先頭コメントや前後 trivia は含めない。window の場合は「最初の文の start」から「最後の文の end」まで。
- **id 生成**:
  - 規約: `${filePath}#${startLine}-${endLine}-${kind}`。
  - 同じ範囲と kind がぶつかる可能性 (例: 同一行に 2 つのアロー関数) に備え、ぶつかったら末尾に `-2`, `-3` ... を付与する (訪問順で確定 → 決定的)。
  - filePath は呼び出し側から渡された「相対パス」をそのまま使う (抽出関数は絶対/相対の変換はしない)。
- **astNodeKind**: `ts.SyntaxKind[node.kind]` の文字列化 (例: `"FunctionDeclaration"`, `"IfStatement"`, `"ArrowFunction"`)。window は `"StatementWindow"` という固定文字列。
- **パース失敗**: `ts.createSourceFile` は (古典 TS では) エラーを throw しない。`sourceFile.parseDiagnostics` が空でない場合は警告を返すのではなく、**抽出可能な部分は抽出する**。コメントだけ出す / silent でいくかは呼び出し側 (M7) が決める。M1 では `parseDiagnostics` を無視してもよい (抽出は best-effort)。

### API

```ts
export interface ParsedSource {
  readonly filePath: string;
  readonly sourceFile: ts.SourceFile;
}

export function parseSource(filePath: string, text: string): ParsedSource;

export function extractFragments(
  parsed: ParsedSource,
  config: Config,
): Fragment[];

export interface SourceInput {
  path: string;   // 相対パス (そのまま Fragment.filePath になる)
  text: string;
}

export function buildCodebaseIndex(
  sources: readonly SourceInput[],
  config: Config,
): Fragment[];
```

## 判定ロジック

### function 系

以下のノードで fragment を生成:

- `FunctionDeclaration`
- `MethodDeclaration`
- `ArrowFunction`
- `FunctionExpression`
- `Constructor`  (class constructor)
- `GetAccessor` / `SetAccessor`

body がない (ambient declaration 等) 場合は fragment を作らない。

### block 系

以下のノードで fragment を生成:

- `IfStatement`
- `ForStatement` / `ForInStatement` / `ForOfStatement`
- `WhileStatement` / `DoStatement`
- `TryStatement` (try 本体)
- `CatchClause`
- `SwitchStatement`

ネストに関わらず全て拾う (内側も外側も fragment になる)。

### window 系

`SourceFile | Block | ModuleBlock | CaseClause | DefaultClause` の `statements` 配列に対して、各 window size と stride でスライディングする。例: statements.length = 12, size = 5, stride = 3 → [0..4], [3..7], [6..10], [9..11 が 3 要素しかないので size 未満: 破棄] だが、**末尾フォールバック**として「最後の文を終端に含む window」を追加する。具体的には:

```
for start = 0; start + size <= N; start += stride:
  emit window(start, start + size - 1)
if last emitted end != N - 1 and N >= size:
  emit window(N - size, N - 1)
```

短いファイル向けの小サイズフォールバック:
```
if N >= 2 and N < min(statementWindowSizes):
  emit window(0, N - 1)  // 全体を 1 window
```

重複した range は同一 id にならないよう disambiguator を付ける (上記 id 規約)。

## テスト

`src/indexer/extractFragments.test.ts` で次をカバー:

1. function declaration が 1 つの fragment として取れる。
2. method / arrow / function expression が別 fragment として取れる。
3. `if` / `for` / `while` がそれぞれ block fragment として取れる。
4. ネストされた `if` の中の `for` が、**外側 if** と **内側 for** の両方 fragment として取れる。
5. statement window が指定された size と stride で生成される (size を変えるとカウントが変わる)。
6. 行範囲 (startLine / endLine) が元ソースと整合する (抜粋 text も整合)。
7. 決定性: 同じ入力で 2 回抽出した結果の配列が (id 含め) 完全一致する。
8. 短い block フォールバック: 文が 2〜4 件しかない関数でも window fragment が 1 個できる。
9. 同一行に 2 つの arrow function がある場合でも id が衝突しない (disambiguator の確認)。

`src/indexer/buildCodebaseIndex.test.ts` で:

- 複数ファイルの結果を順序安定で連結できる (入力順で並ぶ)。
- 空配列入力 → 空配列出力。

## リスク / 留意点

- **window 爆発**: 大きなファイルで window が多量発生し M3 の索引サイズが膨らむ可能性がある。M1 では「生成する」ことに徹し、上限 / 重複排除は M8 で調整する (YAGNI)。
- **astNodeKind の文字列化**: `ts.SyntaxKind[kind]` は実装依存の文字列だが TypeScript の enum リフレクションは長年安定しているため v1 ではこれで十分。後段 (M2) が SyntaxKind そのものを使いたい場合に備え、生成時の文字列を実装内定数としてミラーしておくと安全。ただし YAGNI。
- **tsx のジェネリック衝突**: `.tsx` は `<T>` をジェネリックとして解釈するかタグとして解釈するかが変わる。`ScriptKind.TSX` を明示的に渡せば問題ない。
- **コメント**: fragment の text にコメントが含まれると M2 の token 抽出側でコメント除去する必要がある。本段ではコメントは含んだまま渡す (M2 の `createScanner` が `setOnError` 側で skip する前提)。
